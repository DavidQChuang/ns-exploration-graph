# Requirements and evidence ledger

Status: proposed contract v0.2, 2026-10-27. This ledger is a verification plan, not evidence of implementation. Every item starts **NOT VERIFIED**. Evidence is **MISSING** until a reviewer records a concrete artifact (test name/output, source location, or benchmark report) and result. A schema or draft document alone does not prove runtime behavior.

## How to use this ledger

Requirement IDs are stable references for implementation, review, and release notes. When a requirement changes, retain its ID and record the contract change; add IDs only for genuinely new requirements. Do not mark a row verified based only on inspection or an unexecuted test.

## Open contract questions for integrator

Track resolutions in `docs/DECISIONS.md` or the appropriate versioned contract before implementation depends on them. Integrator decisions on 2026-10-27 resolved acceptance field names, recursive freshness labels, initial revision 1, and terminal-done dependency behavior; implementation/test evidence is still pending. MCP pinning is owned by the integration lane.

- **Acceptance result naming:** TOOLS says the tool returns “reviewed evidence IDs,” while SPEC captures closure edge IDs and resource-reference IDs. Clarify the exact output fields and whether evidence IDs mean node IDs, revision IDs, edge IDs, resource IDs, or a typed combination.
- **MCP pinning:** TOOLS requires protocol/SDK versions pinned during G0, but no versions are selected. Select versions and supported compatibility range before G5 tests are treated as conformance evidence.
- **Freshness in reads:** `graph_list_nodes` requires “available evidence freshness information,” but its exact field/algorithm is not specified. Define it without weakening recursive freshness used for acceptance and work proposals.
- **Graph creation revision:** CreateGraph writes a first event and returns committed revision, while exact initial graph revision and first-event numbering are not explicitly stated. Define the sequence, consistent with import's destination revision 1.
- **Dependency eligibility details:** dependency edges pin no revisions and are based on current work state, but the treatment of prerequisites that become non-done after a dependent starts running is not fully specified. Clarify the permitted transition/edit behavior and race invariant.
